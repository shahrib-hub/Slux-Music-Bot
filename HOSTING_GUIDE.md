# Slux — Complete Hosting Guide

> This guide takes you from zero to a fully hosted Slux music bot with a live web dashboard.
> Architecture: **frontend + dashboard on Vercel (free)**, **bot backend on Wispbyte (or any Node host)**, connected by a Vercel reverse proxy.

---

## 1. How the deployment works (30-second overview)

```
        Browser (users)
              │  HTTPS
              ▼
   ┌─────────────────────┐        ┌──────────────────────────┐
   │  VERCEL             │ proxy  │  WISPBYTE (backend)      │
   │  - Landing site     │──────► │  - Discord bot           │
   │  - Web dashboard    │  HTTP  │  - REST API (/api/*)     │
   │  - vercel.json      │  + WS  │  - socket.io realtime    │
   │    rewrites /api/*  │        │  - MongoDB connection    │
   └─────────────────────┘        └──────────────────────────┘
```

- The browser **only ever talks to your Vercel HTTPS domain**.
- Vercel's `vercel.json` rewrites forward `/api/*` and `/socket.io/*` requests (including websockets) to your Wispbyte container's `IP:PORT`.
- The backend does **not** need HTTPS, a domain, or any web server config — Vercel handles all of that.
- The dashboard is optional: setting `DASHBOARD_ENABLED=false` runs a pure bot with no web surface at all.

## 4. Discord application setup

1. Go to https://discord.com/developers/applications → **New Application**.
2. **Bot** page:
   - Copy the **token** → this is `DISCORD_TOKEN`.
   - Enable the **Message Content Intent** (privileged intent, required for prefix commands).
3. **OAuth2** page:
   - Copy **Client ID** (`DISCORD_CLIENT_ID`) and **Client Secret** (`DISCORD_CLIENT_SECRET`).
   - You will add a **Redirect URI** later (§8), after you know your Vercel URL:
     ```
     https://YOUR-VERCEL-URL/api/auth/callback
     ```
4. Invite the bot to your server later using the link on the dashboard (or `/invite` in Discord). Required permissions: View Channels, Send Messages, Embed Links, Read Message History, Use External Emojis, Manage Messages, Connect, Speak, **Set Voice Channel Status** (used for the live "now playing" channel status).

> If the bot was invited before this feature existed, grant **Set Voice Channel Status** to the bot's role in Server Settings → Roles, or re-invite with the new link.

## 5. MongoDB Atlas setup

1. Create a free **M0 cluster** at https://www.mongodb.com/cloud/atlas.
2. **Database Access** → add a database user (username + password).
3. **Network Access** → add `0.0.0.0/0` (allow from anywhere — the backend connects outbound).
4. **Connect → Drivers** → copy the connection string. It looks like:
   ```
   mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```
   This is your `MONGODB_URI`.

Generate a session secret on your machine:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

This is your `SESSION_SECRET` (must be 32+ characters).

## 6. Lavalink (music engine)

Slux connects to a **3rd-party Lavalink v4 node** — no Docker or self-hosting needed.

Get connection details from any public Lavalink host. **The node must run the LavaSrc + LavaSearch + LavaLyrics plugins** for search, source resolution and lyrics to work (most public nodes do).

```env
LAVALINK_HOST=lavalink.example.com
LAVALINK_PORT=443
LAVALINK_PASS=your-node-password
LAVALINK_SECURE=true        # wss/https — most hosted nodes use this
LAVALINK_NAME=main
```

**Optional backup node** (automatic failover when the main node is offline or busy):

```env
LAVALINK_BACKUP_HOST=backup.lavalink.example.com
LAVALINK_BACKUP_PORT=443
LAVALINK_BACKUP_PASS=other-password
LAVALINK_BACKUP_SECURE=true
```

Use `/nodes` in Discord anytime to check live node status.

## 7. Wispbyte backend setup

> **Git-driven:** after the one-time setup below, pushing to GitHub updates the backend automatically — `dist/` is committed to the repo, and the startup command pulls it on every boot. No more manual uploads.

### 7.1 Create the server

1. In Wispbyte, create a server with the **Node.js** egg (Node 20+ image — e.g. `ghcr.io/parkervcp/yolks:nodejs_24`).
2. Note the **allocation IP:PORT** (e.g. `78.154.103.53:9944`) — this is your **backend address** for `vercel.json`.

### 7.2 Build locally (on your machine, for each release)

```bash
git clone <your-slux-repo>     # or use your existing copy
cd slux
pnpm install
pnpm build:server
```

This produces `dist/server.js` (the whole backend, ~0.5 MB) and `dist/package.json` (a **runtime-only** manifest — 8 packages → ~65 packages / ~35 MB installed). **Commit `dist/` with your changes** — it is no longer gitignored. The frontend build (`pnpm build`) is not needed locally; Vercel builds it itself.

### 7.3 One-time container setup (Wispbyte console)

Run once in the panel's console (replaces the old manual-upload files with the git checkout; `.env` is untouched):

```bash
cd /home/container
rm -rf node_modules dist
git init
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPO.git
git fetch origin
git checkout -f main        # use 'master' if that's your default branch
```

Then create `/home/container/.env` (see §7.4) if you haven't already.

### 7.4 The backend `.env`

`/home/container/.env` (untracked by git — stays across pulls):

```env
NODE_ENV=production

# The PUBLIC url browsers use — this is your VERCEL url (Vercel proxies to this backend).
# No trailing slash. The Discord OAuth redirect is ${APP_URL}/api/auth/callback
APP_URL=https://YOUR-VERCEL-URL.vercel.app

HOST=0.0.0.0
# PORT is read automatically from the panel's allocation — no need to set it.

DISCORD_TOKEN=your-bot-token
DISCORD_CLIENT_ID=your-application-id
DISCORD_CLIENT_SECRET=your-oauth-client-secret

MONGODB_URI=mongodb+srv://...

SESSION_SECRET=your-32-plus-char-random-hex

# Dashboard master switch (true = dashboard enabled)
DASHBOARD_ENABLED=true
# DASHBOARD_URL is optional — it defaults to APP_URL.

LAVALINK_HOST=lavalink.example.com
LAVALINK_PORT=443
LAVALINK_PASS=your-node-password
LAVALINK_SECURE=true
LAVALINK_NAME=main
```

> **Optional — pure bot, no dashboard:** set `DASHBOARD_ENABLED=false`. The API and socket server turn off, dashboard links disappear from bot embeds, and `DISCORD_CLIENT_SECRET` / `SESSION_SECRET` are no longer required. You can then skip the Vercel sections entirely.

### 7.5 Panel startup configuration

In the Wispbyte **Startup** tab, replace the startup command with:

```bash
cd /home/container; git pull --ff-only origin main 2>&1 | tail -1; if [ ! -f dist/.installed ] || ! diff -q dist/package.json dist/.installed >/dev/null 2>&1; then (cd dist && (npm install --omit=dev --no-audit --no-fund --loglevel=error || npm install --omit=dev --no-audit --no-fund --loglevel=error)) && cp dist/package.json dist/.installed; fi; node dist/server.js
```

What it does on every boot:

1. **`git pull`** — picks up your latest push (dist/server.js + everything else)
2. **Dependency check** — installs the 8 runtime packages into `dist/node_modules` only when missing or when `dist/package.json` changed (never installs the ~800-package frontend tree — no OOM)
3. **`node dist/server.js`** — starts the backend

Also set in the Startup tab:

| Variable | Value |
|---|---|
| `AUTO_UPDATE` | `0` (our command handles pulling itself) |

### 7.6 Start and verify

Successful boot log:

```
[slux] Booting backend...
[slux] Loaded 62 commands
[slux] Backend ready on https://YOUR-VERCEL-URL.vercel.app (bound to 0.0.0.0:9944) — ...
[slux] MongoDB connected
[slux] Discord login (attempt 1)…
[slux] Discord gateway connected
[slux] Logged in as YourBot#0001 (N guilds)
[slux] Registered 62 slash commands
[slux] Lavalink node "main" ready
```

The line `(bound to 0.0.0.0:9944)` must show **the panel's allocated port** — the backend reads the panel's port injection automatically.

### 7.7 Optional: fully automatic restart on push

Without this, pushing updates Vercel instantly but the backend picks changes up on its next restart (click Restart in the panel). To make pushes restart the backend too:

1. In GitHub, create the workflow via the **web UI** (Settings → Actions → New workflow, or commit `.github/workflows/restart-backend.yml` through github.com — pushing workflow files from your PC needs a PAT with the `workflow` scope). Copy the content from **`.github/restart-backend.yml.example`** in the repo.
2. Follow the comments in that file: add `PANEL_API_URL` / `PANEL_API_KEY` / `PANEL_SERVER_ID` as GitHub **secrets** and `PANEL_AUTO_RESTART=true` as a repo **variable**.

## 8. Vercel frontend setup

### 8.1 Point the proxy at your backend

In the repo root, edit **`vercel.json`** and replace the placeholder with your Wispbyte allocation address from §7.1:

```json
{
  "rewrites": [
    {
      "source": "/api/(.*)",
      "destination": "http://YOUR-WISPBYTE-IP:PORT/api/$1"
    },
    {
      "source": "/socket.io/(.*)",
      "destination": "http://YOUR-WISPBYTE-IP:PORT/socket.io/$1"
    }
  ]
}
```

Example: `"destination": "http://78.154.103.48:9836/api/$1"`. Commit and push.

### 8.2 Deploy

1. Go to https://vercel.com → **Add New → Project** → import the repo.
2. Settings:
   - **Root Directory:** `./` (repo root — leave default)
   - **Framework Preset:** Next.js (auto-detected)
   - Build/install commands: leave defaults (`pnpm build` / `pnpm install`)
3. Environment Variables — add **only one**:

   | Name | Value |
   |---|---|
   | `NEXT_PUBLIC_DISCORD_CLIENT_ID` | your Discord application id |

   > Do **NOT** set `NEXT_PUBLIC_API_URL` — the `vercel.json` rewrites keep everything same-origin.
4. Deploy and note your URL, e.g. `https://slux.vercel.app`.

### 8.3 Finish the backend wiring

1. Set `APP_URL=https://slux.vercel.app` (your real Vercel URL) in the Wispbyte `.env` (§7.4) and **restart the Wispbyte server**.
2. Discord portal → OAuth2 → Redirects → add **exactly**:
   ```
   https://slux.vercel.app/api/auth/callback
   ```

## 10. Updating the bot later

The whole flow is git-driven — one push updates everything:

```bash
# on your machine
pnpm build:server          # refresh dist/server.js + dist/package.json (bot changes)
git add -A
git commit -m "update"
git push
```

- **Vercel** redeploys the frontend automatically
- **Wispbyte** picks it up on its next restart (startup command pulls) — click Restart in the panel, or set up the auto-restart action from §7.7 for fully hands-free updates

Frontend-only changes don't need `pnpm build:server` — just push.

## 11. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Panel stops the server ~30s after boot / bot never logs in | Backend bound to wrong port (log shows `bound to 0.0.0.0:3001` instead of the allocated port) | Re-upload the current `dist/server.js` — it reads the panel's port automatically. Log must show `(bound to 0.0.0.0:<allocated port>)` |
| `npm install` gets `Killed` | Container RAM too small for the install | The startup command installs only the 8 runtime deps into `dist/node_modules` — make sure you're using it (§7.5). Delete a partial `dist/node_modules` and retry. Last resort: more RAM |
| `ERR_MODULE_NOT_FOUND: Cannot find package '...'` from `dist/server.js` | `dist/node_modules` missing/incomplete | The startup command installs it automatically — check its output; or run `(cd dist && npm install --omit=dev --no-audit --no-fund)` in the panel console |
| Website loads but API errors / no data | `vercel.json` rewrites wrong or backend down | Check the backend address in rewrites; verify backend is running; test `https://vercel-url/api/stats` directly |
| Login loops / "unauthorized" | OAuth redirect mismatch | Portal redirect must **exactly** equal `https://YOUR-VERCEL-URL/api/auth/callback`, and backend `APP_URL` must equal the Vercel URL (no trailing slash, no IP address) |
| Realtime not updating in dashboard / "socket disconnected" on controls | Polling transport flaps through the Vercel proxy (fixed: the dashboard forces websocket-only), or `/socket.io/(.*)` rewrite missing | Redeploy the current frontend (websocket transport is built in); add the socket.io rewrite in `vercel.json`. If the backend log shows "Socket handshake rejected for origin …", set `APP_URL` to the Vercel URL |
| `Discord login still pending after 60s` in log | Container can't reach discord.com (outbound blocked) | Contact host / check container network egress on port 443 |
| Bot connects but no music, "engine not connected" errors | Lavalink node unreachable | Check `LAVALINK_HOST/PORT/PASS/SECURE`; run `/nodes`; try `LAVALINK_SECURE=true` for TLS nodes |
| YouTube "Sign in to confirm you're not a bot" | Lavalink provider's IPs rate-limited by YouTube | Ask your Lavalink provider or switch nodes (other sources unaffected) |
| Voice channel shows no song status | Missing permission | Grant the bot's role **Set Voice Channel Status**, or re-invite with the current invite link |
| Disk slowly filling up | npm cache growth | Run `npm cache clean --force` in the panel console |

## 12. Quick reference — who holds what

| Piece | Where | Notes |
|---|---|---|
| Bot token, OAuth secret, session secret, DB, Lavalink creds | Wispbyte `.env` | All secrets live **only** on the backend |
| `NEXT_PUBLIC_DISCORD_CLIENT_ID` | Vercel env vars | The only frontend env — it's public by design |
| `vercel.json` backend address | Repo (deployed to Vercel) | Update if your Wispbyte allocation changes |
| Discord OAuth redirect | Developer portal | `https://YOUR-VERCEL-URL/api/auth/callback` |
| `APP_URL` on backend | Wispbyte `.env` | Must equal the **Vercel** URL |
